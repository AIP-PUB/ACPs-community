# ACPs-Cred 智能体业务模块源码（2.0.0）

本目录收录四份智能体业务模块，供社区阅读和集成。四份 Python 源文件保留提交者提供的文件名与内容。

| 文件 | 作用 | 主要输入 |
| --- | --- | --- |
| `01_智能体生成器_2.0.0(1).py` | 生成带八项边界与验收项的智能体方案和 ACS 草案 | `requirement`、`evidence`，可选 `previous`、`review` |
| `02_文献查找智能体_2.0.0(1).py` | 检索 Crossref 题录，抓取网页并保留逐字引文与证据缺口 | `query`，可选 `urls` |
| `03_Cred能力核验智能体_2.0.0(1).py` | 分析方案声明，或核验 HMAC 观测记录并汇总能力评分 | `mode=review` 与 `plan`；或 `aic`、可选 `skill_id`、`evidence` |
| `04_输出整理智能体_2.0.0.py` | 整理文本，循环评估五项质量维度并检查引用保留 | `text`，可选 `purpose`、`tone` |

## 当前交付范围

这些文件是业务模块源码，**尚不是可独立启动的完整应用**：它们均以相对导入方式依赖 `.common`，而本次提交不包含 `common.py`、平台适配层、模型配置、证书或部署脚本。不能直接使用 `python 文件名.py` 作为启动方式，也不声明已在梧桐平台完成注册、审核或部署。

集成时应将业务文件放入 Python 包，按需要赋予可导入的模块名，并提供同包内的 `common.py`。每个业务模块通过 `run(payload)` 接收字典并返回字典。

需要的公共接口由源码调用方式推导：

| 接口 | 调用约定 |
| --- | --- |
| `ServiceUnavailable` | 模型服务或返回结构不可用时使用的异常类型 |
| `llm(system, payload)` | 接收系统提示与业务输入，返回已解析的 JSON 对象；不可用时抛出 `ServiceUnavailable` |
| `request(url, timeout=..., public=True)` | 返回正文字符串与响应头；公共 URL 的地址校验、重定向及网络访问限制须在实现中完成 |
| `json_request(url, payload=None, timeout=..., public=...)` | 发起请求并返回已解析的 JSON；代码同时包含 GET 与带请求体的调用 |
| `now()` | 返回用于来源记录和查询记录的时间戳 |
| `digest(record)` | 返回用于 HMAC 的规范化摘要字符串；签名与验签两端须使用完全相同的规范化方式 |

本目录未虚构或补写这些公共服务的实现。业务代码自身使用 Python 标准库；完整应用的第三方依赖取决于公共层。

## 配置与边界

Cred 模块从环境变量读取 `EVIDENCE_HMAC_KEY`、`EVIDENCE_STORE_FILE` 和 `DISCOVERY_LOOKUP_URL`。应在运行环境中配置，勿将真实密钥、原始观测数据、账号凭据或个人路径提交到仓库。模型所需配置由公共层管理。

- 方案生成器中的 `protocolVersion=02.02` 是代码内的草案目标值，不代表本贡献已验证所有平台要求。
- 文献查找的 `verified=True` 表示网页抓取与引文抽取过程完成，不等于网页全部主张为真；Crossref 题录候选未读取全文。当前仅处理 HTML/纯文本等内容，不提供 PDF 原文抽取。
- Cred 的方案评审模式与实证评分是两种不同输出。HMAC 只表示持有共享密钥的采集器见证，不提供独立第三方身份认证；`authenticated_caller` 仍需可信采集器保证。
- Cred 的 `cred-v1` 规则是成功率 0.70、来源多样性 0.15、新鲜度 0.15 的加权和，至少五个非中性样本才输出总分。90 天仅参与新鲜度计算，较旧的有效记录仍进入成功率分母。该规则与另行投稿的 `acps-cred-algo` Wilson 多因子评分不同。
- 输出整理的质量判定来自模型对照评估与引用机械检查，不是外部事实核查。真实效果仍需模型服务与实际任务验证。
